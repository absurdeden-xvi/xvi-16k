# XVI 设计评审格式

对大型审查或探索任务使用以下结构。小修改可以缩短，但不要跳过任务边界和批准状态。

## 任务边界

- 层级：应用界面 / 导出刊页 / 品牌与 Logo
- 模式：审查 / 方向探索 / 实现 / 验证
- 当前状态：已确认 / 强偏好 / 暂定 / 待探索
- 本轮不处理：列出明确排除的范围

## 观察与诊断

按影响排序列出问题。每项包含：

- 用户正在完成的动作；
- 可观察到的阻力；
- 视觉或交互原因；
- 截图、视口或文件依据。

## 必须保留

列出不能因为重设计而丢失的功能、内容、状态和品牌关系。

## 方向比较

每轮最多三种方向，并使用相同内容和功能进行比较。

## 建议与批准门槛

- 推荐方向或仍待回答的问题：
- 可以直接实现的部分：
- 必须等待确认的部分：
- 禁止顺带修改的部分：

## 实现后验证

- 桌面真实页面；
- iPhone 实际尺寸或镜像；
- Android 浏览器；
- 预览与导出一致性；
- 文本、草稿、字体与格式状态保留；
- 视觉回归截图。

## 决策记录

只在用户明确确认后记录：

- 接受了什么；
- 否决了什么；
- 原因是什么；
- 哪些问题仍为待探索。
